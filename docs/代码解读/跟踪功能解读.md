# Sparse4D 跟踪功能解读

本文梳理 Sparse4D 在推理阶段生成目标跟踪 ID 的原理、链路与关键实现位置，帮助理解多帧检测-跟踪一体化流程。

## 1. 整体思路

Sparse4D 通过一个可学习的 `InstanceBank` 来在帧间缓存实例特征与锚点信息。推理时，当前帧的检测查询会与历史缓存进行匹配，从而为持续存在的目标沿用旧 ID，同时为新出现的目标分配全局唯一的新 ID。核心流程如下：

1. `Sparse4DHead.forward` 获取实例库中缓存的查询初值，与当前帧特征共同迭代更新；
2. 推理结束后，将本帧最可信的实例写回实例库缓存；
3. 调用 `InstanceBank.get_instance_id`：
   - 给已有匹配的实例沿用历史 ID；
   - 根据置信度阈值为剩余未匹配实例分配新 ID；
   - 维护一个递增的 `prev_id`，保证跨帧唯一。

## 2. 关键入口：`Sparse4DHead`

- `projects/mmdet3d_plugin/models/sparse4d_head.py:200` 附近：调用 `self.instance_bank.get(...)` 取出历史缓存信息，得到本帧初始查询。
- `projects/mmdet3d_plugin/models/sparse4d_head.py:442-449`：推理阶段缓存最新结果，并通过实例库生成最终的 `instance_id`。

该 Head 将分类得分 `cls`、锚点 `anchor` 等信息传入实例库，以便 ID 生成时参考当前可信度和历史缓存。

## 3. 实例库 `InstanceBank` 的角色

文件位置：`projects/mmdet3d_plugin/models/instance_bank.py`

主要职责：

- **缓存状态**：`self.cached_feature`、`self.cached_anchor`、`self.instance_id` 等字段保存上一帧的高置信度实例；
- **帧间对齐** (`get` 方法，`82-157` 行)：根据时间戳、位姿将历史锚点投影到当前坐标系，并过滤超出时间窗口的实例；
- **缓存更新** (`cache` 方法，`189-215` 行)：挑选当前帧的高置信度实例写回缓存，记录其置信度用于后续匹配；
- **ID 分配** (`get_instance_id` 方法，`217-236` 行)：核心逻辑，详见下一节；
- **历史 ID 维护** (`update_instance_id` 方法，`238-254` 行)：保留一定数量的高置信度实例 ID，供下一帧直接复用。

## 4. ID 生成细节

`InstanceBank.get_instance_id` 的流程：

1. **置信度整理**：对分类分数取每个实例的最大类别置信度并过 `sigmoid`，形成 `[B, N_anchor]` 的置信度矩阵。
2. **填充历史 ID**：若 `self.instance_id` 中存在上一帧保留的 ID，则直接拷贝到当前结果中对应位置，实现“沿用”。
3. **筛选需新建的实例**：对仍为 `-1` 的位置应用阈值（一般来自解码器 `score_threshold`），确定需要新 ID 的实例。
4. **分配新 ID**：
   - 计算新实例数量 `num_new_instance`；
   - 通过 `torch.arange(num_new_instance) + self.prev_id` 生成连续 ID；
   - 写入实例矩阵，并更新 `self.prev_id += num_new_instance`，确保全局唯一。
5. **维护缓存 ID**：若配置了时序缓存 (`num_temp_instances > 0`)，调用 `update_instance_id` 选出置信度最高的若干实例，把它们的 ID 留到 `self.instance_id` 中，供下一帧直接继承。

## 5. reset 逻辑

当批量大小变化或时间间隔超过 `max_time_interval` 时，`InstanceBank.get` 会触发 `self.reset()`（`73-81` 行），清除缓存并将 `prev_id` 重置为 `0`。这等价于开始新的序列，避免跨视频流 ID 冲突。

## 6. 配置入口

`InstanceBank` 的超参数在模型配置中指定，例如 `projects/configs/sparse4dv3_temporal_r50_1x8_bs6_256x704.py:152-182`：

- `num_temp_instances` 控制保留多少历史实例参与时序关联；
- `confidence_decay` 决定历史置信度的衰减系数，避免旧目标长期占据缓存；
- `max_time_interval`、`default_time_interval` 用于处理帧率不稳定的情况。

## 7. 总结

Sparse4D 的跟踪能力来自于统一的查询实例库：

- 通过缓存与时间投影，让跨帧实例可以共享 ID；
- 利用置信度筛选机制和递增的 `prev_id` 实现稳定的 ID 分配；
- `Sparse4DHead` 在推理输出前调用实例库生成最终的 `instance_id`，完成检测与跟踪的结合。

掌握上述关键函数的位置和职责，可快速定位跟踪相关逻辑，并根据需求调整时序缓存策略或 ID 策略。
